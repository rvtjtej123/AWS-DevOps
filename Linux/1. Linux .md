## **What is Linux?**

Linux is an **Operating System (OS)**.

An operating system manages computer hardware and allows users and applications to interact with the system.

### **Examples of Operating Systems**

```text
Windows → Operating System
macOS   → Operating System
Linux   → Operating System
```

---

## **What is a Server?**

A server can be understood as a combination of:

```text
Hardware
   +
Operating System
   +
Server Software / Services
   =
Server
```

For example:

```text
Computer Hardware
        +
Amazon Linux
        +
Apache Tomcat
        =
Application Server
```

A server provides services to users or other computers.

---

These terms are sometimes used to refer to a computer or computing environment.

```text
Server
Machine
Box
```

They can often mean a computer, depending on the context.

### **Instance**

In cloud computing, an **Instance** usually means a virtual server.

**Example:**

```text
AWS EC2 Instance
```

```text

EC2 Instance → Virtual Server
```

## **Windows and Linux**

Both Windows and Linux use locations to organise files.

```text
Windows → Usually called Folder
Linux   → Usually called Directory
```

Example:

```text
Windows:

C:\Users\Username\Documents
```

```text
Linux:

/home/ec2-user/documents
```

## **User Accounts in Linux**

Linux supports multiple user accounts.

The two important types are:

### **1. Normal User**

A normal user has **limited permissions**.

Examples:

```text
ec2-user
ubuntu
ravi
```

A normal user may require `sudo` to perform administrative tasks.

Example:

```bash
sudo dnf install nginx
```

---

### **2. Root User / Superuser**

The root user has **full permissions** on the Linux system.

```text
root
```

The root user can:

- Install or remove software
- Create or delete users
- Change system configuration
- Access system files
- Modify permissions

### **Easy Understanding**

```text
Normal User → Limited Permissions

Root User → Full Permissions
```

Normally, a user can use `sudo` when administrative permission is required.

```text
Normal User
     ↓
Use sudo
     ↓
Administrative Permission
```

## **Deploying Applications**

An application can be deployed on a server.

### **Simple Example**

```text
One Server
     ↓
One Application
```

Example:

```text
EC2 Server
     ↓
Apache Tomcat
     ↓
Java Application
```

---

## **Multiple Applications**

Multiple applications can also run on the same server.

```text
One Server
   ├── Application 1
   ├── Application 2
   └── Application 3
```

However, this can sometimes cause:

- Resource conflicts
- Port conflicts
- Difficult management
- One application's failure affecting other applications

---

## **Using Separate Servers**

Applications can also be deployed on separate servers.

```text
Application 1
      ↓
Server 1


Application 2
      ↓
Server 2
```

This provides better isolation.

If one application has a major problem, the other application may remain unaffected.

---

## **Containers**

Using containers, multiple applications can run separately on the same infrastructure.

```text
Server
   ↓
Containers
   ├── Application 1
   ├── Application 2
   └── Application 3
```

Docker is commonly used to create containers.

Kubernetes can be used to manage multiple containers.

## **AWS Resource Cleanup**

After completing practice in AWS, check for resources that are no longer required.

Some AWS resources may continue to generate charges if they remain active or allocated.

Examples:

```text
EC2 Instance
EBS Volume
Elastic IP
Load Balancer
NAT Gateway
RDS Database
```

### **Recommended Process**

```text
Complete Practice
        ↓
Check AWS Resources
        ↓
Stop or Terminate Unused Resources
        ↓
Delete Unnecessary Chargeable Resources
```

> **Note:** Terminating an EC2 instance may not automatically delete every related resource. Always check for remaining EBS volumes, snapshots, Elastic IPs, and other AWS resources.
