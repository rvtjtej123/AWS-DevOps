# USER MANAGEMENT — DAY 17

> **EL5 idea:**  
> Linux has users and groups.  
> A **user** is a person/account that can log in or run processes.  
> A **group** is a collection of users used to manage permissions more easily.  
> Linux stores user and group information mainly in files such as `/etc/passwd`, `/etc/shadow`, and `/etc/group`.

---

# 1. Default Linux Users

### Handwritten note:
> Default Linux user: `ec2-user` and `root`  
> Normal user

### Explanation

There is **no universal default username for every Linux distribution**.

- `root` → the administrator/superuser account. Its UID is normally `0`.
- `ec2-user` → commonly used as the default login user on **Amazon Linux EC2 AMIs**.
- Other distributions use different default users. For example, Ubuntu cloud images commonly use `ubuntu`.

So the note is correct **in the Amazon Linux/EC2 context**, but not for Linux in general.

---

# 2. Important User-Management Files

## `/etc/passwd`

### Handwritten note:
> `/etc/passwd` = We can find all the users information.

### Correct explanation

`/etc/passwd` contains **user account information**.

It does **not normally contain the actual user passwords**.

A typical entry looks like:

```text
username:x:1001:1001::/home/username:/bin/bash
```

The seven fields are:

```text
name : password : UID : GID : GECOS : home-directory : login-shell
```

### Meaning of each field

| Field | Meaning |
|---|---|
| `username` | Login/user name |
| `x` | Password information is stored in `/etc/shadow` |
| `1001` | UID — User ID |
| `1001` | GID — primary Group ID |
| empty field | GECOS/comment information |
| `/home/username` | User's home directory |
| `/bin/bash` | User's login shell |

The `/etc/passwd` format and the meaning of UID, GID, home directory and shell are defined by the Linux password-file specification.

---

# 3. `/etc/shadow`

### Handwritten note:
> `/etc/shadow` = All the users password.

### Correction

This statement is **not technically accurate**.

`/etc/shadow` contains **password hashes and password/account aging information**, not plaintext passwords.

A password is normally converted into a cryptographic hash and the resulting password information is stored in `/etc/shadow`.

A normal user should not be able to read this file because it contains sensitive authentication information.

Example:

```text
username:$6$...:...
```

The long string beginning with something such as `$6$` is a password hash, **not the original password**.

### Important distinction

```text
/etc/passwd  → user/account information
/etc/shadow  → password hash + password/account aging information
/etc/group    → group information
/etc/gshadow  → secure group information
```

# 4. Find All Usernames

### Handwritten note:

```text
cat /etc/passwd
```

### What does it do?

It displays the contents of `/etc/passwd`.

Because every user entry is stored as a line in `/etc/passwd`, this lets you see the accounts known through that file.

### Command breakdown

```text
cat /etc/passwd
```

- `cat` → displays the contents of a file.
- `/etc/passwd` → the Linux user-account database file being displayed.

### Example

```bash
cat /etc/passwd
```

You will see lines similar to:

```text
root:x:0:0:root:/root:/bin/bash
ec2-user:x:1000:1000::/home/ec2-user:/bin/bash
```

### Better way to remember

```text
cat /etc/passwd
        ↓
   user account information
```

# 5. Find Password Information

### Handwritten note:

```text
cat /etc/shadow
```

### Correct explanation

This displays `/etc/shadow`, which contains password hashes and password-aging information.

However, this normally requires root privileges.

```bash
sudo cat /etc/shadow
```

### Command breakdown

- `sudo` → execute the command with elevated privileges.
- `cat` → display file contents.
- `/etc/shadow` → secure password/account-aging database.

### VERY IMPORTANT

```text

```

It displays password hashes and related information.

Do not casually expose or copy `/etc/shadow`; it is sensitive security information.

# 7. Understanding UID and GID

The handwritten note shows:

```text
username:1001:1001::/home/username:/bin/bash
```

The important numbers are:

```text
username:x:1001:1001::/home/username:/bin/bash
         │    │
         │    └── GID
         └─────── UID
```

### UID

**UID = User ID**

It is the numerical identity of the user.

Example:

```text
ravi:x:1001:1001::/home/ravi:/bin/bash
       ↑
      UID
```

### GID

**GID = Group ID**

It represents the user's primary group.

```text
ravi:x:1001:1001::/home/ravi:/bin/bash
            ↑
           GID
```

`userdel` removes a user account.


### Command breakdown

- `sudo` → run with administrative privileges.
- `userdel` → delete a user account.

# 11. Delete a User and Their Home Directory

### Handwritten note:

> Delete the username with home directory:
>
> `userdel -r username`

This is the preferred method when you intentionally want to remove the user's home directory as part of deleting the account.

```bash
sudo userdel -r username
```

### Command breakdown

- `sudo` → administrative privileges.
- `userdel` → delete the user.
- `-r` / `--remove` → remove the user's home directory and mail spool along with the account.
- `username` → account being deleted.

Example:

```bash
sudo userdel -r ravi
```

### Important limitation

`userdel -r` removes the user's home directory and mail spool, but files belonging to the user elsewhere on the filesystem may remain.

Those files need to be located and handled separately.

# 12. Manually Removing a Home Directory

### Handwritten notes:

```text
cd home
ls
rm -rf username
```

The note shows this as another way to delete the home directory.

### Better/safe form

```bash
cd /home
ls
sudo rm -rf username
```

### Command 1

```bash
cd /home
```

- `cd` → change directory.
- `/home` → directory containing normal users' home directories on many Linux systems.

### Command 2

```bash
ls
```

- `ls` → lists files/directories.
- Here it lets you check which home directories exist.

### Command 3

```bash
sudo rm -rf username
```

- `sudo` → administrative privileges.
- `rm` → remove files/directories.
- `-r` → recursively remove a directory and its contents.
- `-f` → force removal without normal confirmation.
- `username` → the home directory being removed.

### WARNING

`rm -rf` is dangerous.

For example:

```bash
sudo rm -rf /home/ravi
```

can permanently delete the directory and its contents.

For normal user deletion, prefer:

```bash
sudo userdel -r ravi
```

because it performs account-related cleanup as part of the user-deletion operation.


This creates:

```text
Group name = developers
GID        = 3344
```

# 16. Create a Custom User

### Handwritten note:

```bash
useradd -u 1122 -g 3344 -c "comments" -d /opt/username -s /bin/zsh -m Docker
```

This is the complete custom-user example from the notes.

A cleaner equivalent with administrative privileges is:

```bash
sudo useradd -u 1122 -g 3344 -c "comments" -d /opt/username -s /bin/zsh -m Docker
```

## What does it do?

It creates a user named:

```text
Docker
```

with a specified UID, primary group, comment, home directory, login shell, and home-directory creation.

## Option-by-option explanation

### `useradd`

Creates the user account.

---

### `-u 1122`

```text
-u = UID
1122 = requested user ID
```

So:

```bash
-u 1122
```

means:

> Give the new user UID `1122`.

The UID normally must be unique.

---

### `-g 3344`

```text
-g = primary group
3344 = GID
```

So:

```bash
-g 3344
```

means:

> Make the existing group with GID `3344` the user's primary group.

**Important:** the group must already exist.

For example:

```bash
sudo groupadd -g 3344 developers
```

Then:

```bash
sudo useradd -u 1122 -g 3344 ...
```

can use that group as the user's primary group.

---

### `-c "comments"`

```text
-c = comment/GECOS field
"comments" = text stored in the comment field
```

Example:

```bash
-c "Docker user"
```

This stores descriptive information about the account.

---

### `-d /opt/username`

```text
-d = home directory
/opt/username = desired home-directory path
```

This tells `useradd` to use:

```text
/opt/username
```

as the user's home directory.

### Important correction

If the actual username is `Docker`, you might instead expect:

```bash
-d /opt/Docker
```

unless `/opt/username` is intentionally the desired literal directory name.

---

### `-s /bin/zsh`

```text
-s = login shell
/bin/zsh = shell program
```

This tells Linux to use `/bin/zsh` as the user's login shell.

The shell must actually exist on the system.

Check it with:

```bash
ls -l /bin/zsh
```

---

### `-m`

```text
-m = create home directory
```

This tells `useradd` to create the user's home directory if it does not already exist and copy the appropriate skeleton files.

---

### `Docker`

This is the **username/login name** being created.

So the command can be mentally read as:

```text
Create user Docker
with UID 1122
using primary GID 3344
with comment "comments"
with home directory /opt/username
using /bin/zsh
and create the home directory.
```

# 17. Change a User's UID

### Handwritten note:

```bash
usermod -u 1100 username
```

### What does it do?

Changes the UID of an existing user.

```bash
sudo usermod -u 1100 username
```

### Command breakdown

- `sudo` → administrative privileges.
- `usermod` → modifies an existing user account.
- `-u` → specify a new UID.
- `1100` → new UID.
- `username` → user being modified.

Example:

```bash
sudo usermod -u 1100 ravi
```

This changes `ravi`'s UID to `1100`.

### Important

Changing a UID can affect file ownership.

Files outside the user's home directory that belonged to the old UID may need to be handled manually.

Also, the user should not be actively running processes while making major identity changes such as UID changes.

# 18. Change a Username

### Handwritten note:

```bash
usermod -l newusername oldusername
```

### What does it do?

Changes the login name from `oldusername` to `newusername`.

```bash
sudo usermod -l newusername oldusername
```

### Command breakdown

- `sudo` → administrative privileges.
- `usermod` → modify an existing user.
- `-l` → change the login name.
- `newusername` → new login name.
- `oldusername` → existing login name.

Example:

```bash
sudo usermod -l ravi2 ravi
```

This changes:

```text
old username → ravi
new username → ravi2
```

### VERY IMPORTANT

`usermod -l` changes the login name.

It does **not automatically rename the user's home directory**.

For example, `/home/ravi` may still remain `/home/ravi`.

If you want to move/rename the home directory as well, `usermod -d` together with `-m` can be used appropriately.

# 19. Expire a User Account on a Date

### Handwritten note:

```bash
chage -E 2027-08-31 username
```

### What does it do?

Sets the account expiration date.

```bash
sudo chage -E 2027-08-31 username
```

### Command breakdown

- `sudo` → administrative privileges.
- `chage` → changes password/account aging information.
- `-E` / `--expiredate` → sets the account expiration date.
- `2027-08-31` → expiration date in `YYYY-MM-DD` format.
- `username` → user whose account is being changed.

Example:

```bash
sudo chage -E 2027-08-31 ravi
```

This sets the account expiration date for `ravi`.

### Important correction to the concept

Account expiration and password expiration are related but **not the same thing**.

```text
Account expiration
        ↓
The account itself becomes inaccessible after the expiration date.

Password expiration
        ↓
The password must be changed according to password-aging rules.
```

# 22. Change Both Owner and Group

### Handwritten note:

```bash
chown ec2-user:groupname filename
```

### What does it do?

Changes:

```text
owner → ec2-user
group → groupname
```

Example:

```bash
sudo chown ec2-user:developers report.txt
```

### Command breakdown

- `chown` → change ownership.
- `ec2-user` → new file owner.
- `:` → separates owner and group.
- `developers` → new group.
- `report.txt` → target file.

So:

```text
ec2-user:developers
│        │
│        └── new group
└─────────── new owner
```

---

# 23. Change Only the Group

### Handwritten note:

```bash
chown :groupname filename
```

### What does it do?

Changes only the group ownership.

The owner remains unchanged.

Example:

```bash
sudo chown :developers report.txt
```

### Command breakdown

- `chown` → change ownership.
- empty part before `:` → do not change the owner.
- `developers` → new group.
- `report.txt` → target file.

Conceptually:

```text
current-owner:developers
```

The owner stays the same, while the group becomes `developers`.

### Alternative command

For changing only group ownership, `chgrp` is also specifically designed for this purpose:

```bash
sudo chgrp developers report.txt
```

- `chgrp` → change group ownership.
- `developers` → new group.
- `report.txt` → target file.

# 32. Common Mistakes Corrected from the Handwritten Notes

### Mistake 1

```text
/etc/shadow = all users' passwords
```

❌ Not exactly.

Correct:

```text
/etc/shadow = password hashes + password/account aging information
```

---

### Mistake 2

```text
groupadd -g 3344 groupname
```

means:

```text
create group with custom members
```

❌ No.

It means:

```text
create group with GID 3344
```

Group membership is a separate concept.

---

### Mistake 3

```text
ec2-user always has UID 1000
```

❌ Not universally true.

`1000` is commonly used for the first regular user, and Amazon Linux may use it for `ec2-user`, but the actual machine configuration determines the UID.

---

### Mistake 4

```text
userdel username
```

automatically removes everything belonging to that user.

❌ No.

Use:

```bash
userdel -r username
```

when you intentionally want the user's home directory and mail spool removed too.

Even `userdel -r` does not guarantee that every file owned by that UID everywhere on every filesystem is removed.

---

### Mistake 5

```text
usermod -l newusername oldusername
```

automatically renames `/home/oldusername`.

❌ No.

`-l` changes the login name. The home directory should be handled separately if it also needs to be renamed/moved.

---

### Mistake 6

```text
chage -E date
```

is simply "password expiration".

⚠️ More precisely, `-E` sets the **account expiration date** in the shadow account-aging information. Password aging has separate settings.

---

### Mistake 7

```text
rm -rf username
```

is a harmless way to remove a user's home directory.

❌ Absolutely not.

`rm -rf` is a powerful destructive command. Always verify the exact path before running it.

# 33. EL5 Mental Model

Imagine Linux is a school.

```text
USER
 ↓
A student/person with an identity
```

Every user gets a number:

```text
UID
 ↓
1001
```

Users can belong to groups:

```text
USER
 ↓
ravi
 ↓

 ↓

```

The important files are like school registers:

```text

    ↓
"Who are the students?"

    ↓

    ↓
```

```bash
# Change username
sudo usermod -l newusername oldusername

# Set account expiration date
sudo chage -E 2027-08-31 username

# Display password/account aging information
sudo chage -l username

# Change file owner
sudo chown newowner filename

# Change owner and group
sudo chown newowner:newgroup filename

# Change only group
sudo chown :newgroup filename

# Alternative for changing only group
sudo chgrp newgroup filename

# Delete group
sudo groupdel groupname
```

---

# 35. ONE-LINE MEMORY TRICK

```text
useradd  → ADD user
usermod  → MODIFY user
userdel  → DELETE user

groupadd → ADD group
groupdel → DELETE group

passwd   → PASSWORD
chage    → PASSWORD/ACCOUNT AGING

chown    → CHANGE OWNER
chgrp    → CHANGE GROUP

/etc/passwd → USER ACCOUNT INFO
/etc/shadow → PASSWORD HASH + AGING INFO
/etc/group  → GROUP INFO
```
