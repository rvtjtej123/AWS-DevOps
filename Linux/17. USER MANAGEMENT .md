# 1. WHAT IS USER MANAGEMENT?

## EL5 Explanation

Linux can have many people/accounts using the same computer/server.

For example:

```text
root
ec2-user
alice
bob
docker
```

Each user can have:

- A username
- A UID (User ID)
- A primary GID (Group ID)
- A home directory
- A login shell
- Password/account information
- Group memberships

**User Management** means creating, deleting, modifying, and managing these user accounts.

Linux provides commands such as:

```text
useradd
userdel
usermod
passwd
chage
id
groupadd
groupdel
chown
```

Red Hat documentation also identifies `useradd`, `usermod`, `userdel`, `groupadd`, `groupmod`, and `groupdel` as standard command-line tools for managing users and groups. :contentReference[oaicite:0]{index=0}

# 2. DEFAULT LINUX USERS

The handwritten note says:

```text
Default linux user:
ec2-user and root
normal user
```

### Important clarification

There is no universal "default Linux user" for every Linux distribution.

For an **Amazon EC2 instance**, `ec2-user` is commonly the default login user for Amazon Linux images.

`root` is the Linux superuser.

So, for the Amazon Linux context of these notes:

```text
root
    ↓
Superuser / administrator

ec2-user
    ↓
Normal administrative login user commonly used on Amazon Linux
```

### root

`root` is the superuser and normally has UID:

```text
0
```

The root account has very high privileges.

### ec2-user

On typical Amazon Linux installations, `ec2-user` is a normal user account created for logging into the EC2 instance.

Its UID is commonly:

```text
1000
```

but **do not memorize `1000 = ec2-user` as a universal Linux rule**.

UID assignments are system-dependent.

# 3. `/etc/passwd`

The handwritten note says:

```text
/etc/passwd = We can find all the users information.
```

### Correct meaning

`/etc/passwd` contains account information for users known to the system.

It does **not** normally contain users' actual password hashes on modern Linux systems.

The password field is commonly:

```text
x
```

which indicates that the password information is stored in `/etc/shadow`.

The `/etc/passwd` file contains seven colon-separated fields. :contentReference[oaicite:1]{index=1}

### Example

```text
username:x:1001:1001::/home/username:/bin/bash
```

The fields are:

```text
username
   ↓
login name

x
   ↓
password placeholder
   actual password hash is normally in /etc/shadow

1001
   ↓
UID = User ID

1001
   ↓
GID = primary Group ID

(empty/comment)
   ↓
comment/GECOS field

/home/username
   ↓
home directory

/bin/bash
   ↓
login shell
```

### Exact structure

```text
LOGIN_NAME : PASSWORD : UID : GID : COMMENT : HOME : SHELL
```

Example:

```text
ravi:x:1001:1001::/home/ravi:/bin/bash
```

# 4. `/etc/shadow`

The handwritten note says:

```text
/etc/shadow = All the users password.
```

### Correction

This should be understood as:

```text
/etc/shadow
    ↓
Contains password hashes and password/account aging information.
```

It does **not** normally contain passwords in plain text.

The file is protected and is intended to be readable only by privileged users. :contentReference[oaicite:2]{index=2}

### EL5 Example

Think of:

```text
/etc/passwd
```

as a public employee directory containing:

```text
Name
ID
Home
Shell
```

and:

```text
/etc/shadow
```

as the locked safe containing sensitive password/account information.

# 5. FIND ALL USERNAMES

The handwritten note gives:

```bash

```

### What is it used for?

Displays the contents of `/etc/passwd`.

Since `/etc/passwd` has one entry per user account, this lets you see the user-account entries.

### Breakdown

```text
cat
```

→ Displays the contents of a file.

```text
/etc/passwd
```

→ The file containing user account information.

### Command

```bash
cat /etc/passwd
```

### Example output

```text
root:x:0:0:root:/root:/bin/bash
ec2-user:x:1000:1000:EC2 Default User:/home/ec2-user:/bin/bash
alice:x:1001:1001::/home/alice:/bin/bash
```

### Important

The handwritten note says this finds "all usernames."

More precisely, it displays **all entries in `/etc/passwd`**, including system/service accounts as well as normal human users.

# 18. EXPLAINING EACH `useradd` OPTION

## `-u` → Custom UID

Example:

```bash
-u 1122
```

### Meaning

```text
-u
→ Specify the user's numerical UID.

1122
→ UID assigned to the new user.
```

Example:

```bash
sudo useradd -u 1122 Docker
```

The new user gets UID:

```text
1122
```

The UID normally must be unique unless special options are used. :contentReference[oaicite:8]{index=8}

---

## `-g` → Primary Group

Example:

```bash
-g 3344
```

### Meaning

```text
-g
→ Specify the user's primary group.

3344
→ GID or group identifier of the primary group.
```

### IMPORTANT

The group must already exist.

For example:

```bash
sudo groupadd -g 3344 developers
```

Then:

```bash
sudo useradd -g 3344 Docker
```

makes `developers`/GID `3344` the primary group of `Docker`.

The `useradd` documentation specifies that the group named or numbered by `-g` must already exist. :contentReference[oaicite:9]{index=9}

---

## `-c` → Comment

Example:

```bash
-c "comments"
```

### Meaning

```text
-c
→ Set the comment/GECOS field.

"comments"
→ Text stored in that field.
```

This field is commonly used for information such as the user's full name.

Example:

```bash
sudo useradd -c "Docker User" Docker
```

The comment becomes:

```text
Docker User
```

---

## `-d` → Custom Home Directory

Example:

```bash
-d /opt/username
```

### Meaning

```text
-d
→ Specify the user's home/login directory.

 /opt/username
→ Custom home directory path.
```

### Important

`-d` specifies the path, but it does not by itself guarantee that the directory is created.

That is why `-m` is commonly used with it. :contentReference[oaicite:10]{index=10}

---

## `-s` → Login Shell

Example:

```bash
-s /bin/zsh
```

### Meaning

```text
-s
→ Specify the user's login shell.

 /bin/zsh
→ Shell that will be used when the user logs in.
```

Another common example is:

```bash
-s /bin/bash
```

The shell path should correspond to an available/valid shell on the system.

The handwritten note describes this as:

```text
-m = home directory
```

### More accurately:

```text
-m
→ Create the user's home directory if it does not already exist.
```

It also causes files from the skeleton directory, commonly `/etc/skel`, to be copied into the new home directory. :contentReference[oaicite:11]{index=11}

```bash

```

creates:

```text

```

when `/home` is the configured base directory.

# 19. COMPLETE CUSTOM USER EXAMPLE

```bash
sudo useradd -u 1122 -g 3344 -c "comments" -d /opt/username -s /bin/zsh -m Docker
```

### Complete breakdown

```text
sudo
→ Run with administrator privileges.

useradd
→ Create a new user.

-u 1122
→ Give the user UID 1122.

-g 3344
→ Give the user primary GID 3344.
   The corresponding group must already exist.

-c "comments"
→ Set the account comment/GECOS field to "comments".

-d /opt/username
→ Set the user's home directory to /opt/username.

-s /bin/zsh
→ Set /bin/zsh as the user's login shell.

-m
→ Create the specified home directory if needed.

Docker
→ Username being created.
```

### Prerequisite

Because:

```bash
-g 3344
```

uses GID `3344`, that group should already exist.

For example:

```bash
sudo groupadd -g 3344 docker-group
```

Then:

```bash
sudo useradd -u 1122 -g 3344 -c "comments" -d /opt/username -s /bin/zsh -m Docker
```

# 31. IMPORTANT `-G` OPTION

Although not explicitly written in the notes, it is important when discussing custom groups.

Example:

```bash
sudo usermod -aG developers alice
```

### Breakdown

```text
sudo
→ Administrator privileges.

usermod
→ Modify an existing user.

-a
→ Append; keep the user's existing supplementary groups.

-G
→ Specify supplementary group(s).

developers
→ Group to add.

alice
→ User being modified.
```

### Why is `-a` important?

Do not casually use:

```bash
usermod -G developers alice
```

because `-G` specifies the supplementary-group list, and without `-a`, existing supplementary memberships can be replaced.

Using:

```bash
usermod -aG developers alice
```

means:

> Add `developers` while preserving the existing supplementary groups.

Red Hat documentation gives this form for adding a user to a group. :contentReference[oaicite:22]{index=22}

# 33. EL5 — UNDERSTAND USER MANAGEMENT AS A STORY

Imagine a Linux server is a school.

```text
School
│
├── Students/users
│     ├── Alice
│     ├── Bob
│     └── Docker
│
├── Groups/classes
│     ├── developers
│     ├── testers
│     └── admins
│
└── Files
      ├── file1
      └── file2
```

Each user gets an identity.

```text
Alice
 ↓
UID 1001
```

Each user has a primary group.

```text
Alice
 ↓
GID 1001
```

A user can also belong to additional groups.

```text
Alice
 ↓
developers
testers
```

The system stores the account information in:

```text
/etc/passwd
```

Sensitive password/account information is stored in:

```text
/etc/shadow
```

Group information is stored in:

```text
/etc/group
```

# 39. IMPORTANT CORRECTIONS FROM THE HANDWRITTEN NOTES

```text
1. /etc/passwd does NOT normally contain actual user passwords.
   It contains account information; the password field is commonly "x".

2. /etc/shadow does NOT normally contain plain-text passwords.
   It contains password hashes and password/account aging information.

3. "All usernames" from /etc/passwd is slightly simplified.
   /etc/passwd also contains system/service accounts.

4. UID 0 = root is correct.

5. UID 1000 = ec2-user is NOT a universal Linux rule.
   It is common on Amazon Linux EC2 images.

6. userdel username removes the account, but does not automatically
   mean that the home directory is removed.

7. userdel -r username removes the user's home directory and mail spool.

8. rm -rf username can manually remove a home directory, but it is
   dangerous and should not be used carelessly.

9. groupadd -g 3344 groupname creates a group with GID 3344.
   It does NOT add custom members.

10. -g in useradd specifies the PRIMARY group.

11. -G specifies SUPPLEMENTARY groups.

12. When adding a user to supplementary groups with usermod,
    -aG is normally used so existing supplementary groups are preserved.

13. useradd -m means CREATE the home directory.
    It does not merely mean "home directory."

14. useradd -d specifies the home-directory path.
    -m is what requests creation of that directory.

15. chage -E sets the ACCOUNT expiration date.

16. chage -l lists account/password aging information.

17. chown user file changes the owner.

18. chown user:group file changes both owner and group.

19. chown :group file changes only the group.

20. groupdel cannot normally remove a group that is the primary group
    of an existing user.

21. Changing a UID can require ownership cleanup for files that still
    belong to the old numeric UID.

22. Changing a username does not automatically mean the home directory
    is renamed or moved.
```
