# Linux Services & Cron Jobs — Day 15

## 1. Services

### What is a Service?

A **service** is a program/process that provides some functionality to the system or other programs.

Many services run in the **background**, without the user directly interacting with them.

Think of it like this:

> **Service = a program that performs a job for the system, usually in the background.**

Examples:

- SSH service → allows remote SSH connections.
- Cron service → runs scheduled jobs.
- HTTP service → runs a web server.

---

## 2. SSH and SSHD

### SSH

**SSH = Secure Shell**

SSH is used to securely connect to another Linux/Unix machine over a network.

Example:

```bash
ssh user@server-ip
```

Breakdown:

```text
ssh          → Secure Shell client command
user         → Username on the remote machine
server-ip    → IP address/hostname of the remote machine
```

### Important correction

`ssh` and `sshd` are **not the same thing**.

- `ssh` → **client** command used to connect to another machine.
- `sshd` → **SSH daemon/server** that waits for incoming SSH connections.

---

## 3. SSHD

### SSHD = Secure Shell Daemon

`sshd` is the **SSH server daemon**.

It normally runs in the background and waits for incoming SSH connections.

Think:

```text
Your computer
     |
     | ssh user@server
     ↓
Remote Linux Server
     |
     └── sshd
          ↓
       Accepts SSH connection
```

So:

```text
SSH  → Client
SSHD → Server/Daemon
```

### Why is `sshd` called a daemon?

A **daemon** is a program that normally runs in the background and performs a service.

The `d` in:

```text
sshd
```

stands for **daemon**.

# 4. `service` vs `systemctl`

The handwritten notes mention:

> Service supports up to RHEL-6  
> systemctl supports from RHEL-7  
> RHEL-7 works with both systemctl and service.

The basic idea is correct, but there is an important correction.

### RHEL 6

RHEL 6 primarily used the older **SysV init/service** system.

Example:

```bash
service sshd status
```

### RHEL 7 and later

RHEL 7 introduced **systemd** as the service manager, and `systemctl` became the primary command for managing services.

Example:

```bash
systemctl status sshd
```

The old `service` command remained available for compatibility.

So the better way to remember it is:

```text
RHEL 6
   ↓
service / SysV init

RHEL 7+
   ↓
systemd + systemctl
   ↓
service command may still work for compatibility
```

Therefore, do **not** memorize:

> "`service` does not work after RHEL 6."

That is incorrect.

Instead remember:

> **RHEL 7 introduced systemd/systemctl as the modern service-management system, while `service` remained available for compatibility.**

# 5. Checking a Service

## Command

```bash
service sshd status
```

### Purpose

This checks the status of the `sshd` service.

Breakdown:

```text
service       → Command used to manage a service
sshd          → Name of the SSH daemon/service
status        → Ask for the current status
```

So:

```bash
service sshd status
```

means:

> "Show me the current status of the SSH daemon."

### Modern equivalent

```bash
systemctl status sshd
```

# 6. Stopping a Service

The handwritten note gives:

```bash

```

### Purpose

Stops the `crond` service.

Breakdown:

```text
service       → Manage a service
crond         → Cron daemon/service
stop          → Stop the service
```

If your user does not have sufficient permission:

```bash
sudo service crond stop
```

`sudo` means:

> Run the command with elevated privileges.

### Modern command

```bash
sudo systemctl stop crond
```

```text
sudo          → Run with elevated privileges

start         → Start the service
```

Modern command:


# 8. Restarting a Service

The handwritten note gives:

```bash
sudo service crond restart
```

### Purpose

Restarts the `crond` service.

Usually this means:

```text
Stop the service
      ↓
Start the service again
```

Modern command:

```bash
sudo systemctl restart crond
```

### Important correction to the note

The note says:

> We can only restart a service if it is in Active status.

That is **not completely correct**.

With `systemctl restart`, a service does not necessarily have to already be running. `restart` can start the service if it is not currently running.

If you specifically want:

> Restart it **only if it is already running**

use:

```bash
sudo systemctl try-restart crond
```

# 9. `service` and `systemctl` — Quick Comparison

| Task | Older / compatibility command | Modern command |
|---|---|---|
| Check status | `service sshd status` | `systemctl status sshd` |
| Start | `service crond start` | `systemctl start crond` |
| Stop | `service crond stop` | `systemctl stop crond` |
| Restart | `service crond restart` | `systemctl restart crond` |
| Check active state | — | `systemctl is-active crond` |
| Check boot-enabled state | — | `systemctl is-enabled crond` |

# 10. Amazon Linux 2

The handwritten note says:

> Systemctl works from Amazon Linux 2.  
> We can use both systemctl and service in AWS Linux 2.

For **Amazon Linux 2**, this is essentially correct.

Amazon Linux 2 uses `systemd`, so `systemctl` can be used to manage services.

Examples:

```bash
sudo systemctl status sshd
sudo systemctl start sshd
sudo systemctl stop sshd
sudo systemctl restart sshd
```

The `service` command is also available for compatibility.

### Important

Do not confuse:

```text
Amazon Linux 2
```

with:

```text
Amazon Linux 2023
```

Amazon Linux 2023 is newer and has some important differences.

# 11. CRON

## What is Cron?

**Cron** is used to schedule tasks so that they run automatically at a particular time or at regular intervals.

The handwritten note says:

> Crontab: Schedule tasks to run automatically.

That is the correct basic idea.

Think of Cron as an **alarm clock for Linux**.

For example:

> "Run this script every day at 1 AM."

Instead of manually running the script every day, Cron runs it automatically.

---

# 12. Cron vs Crontab vs Crond

These three names are easy to confuse.

### `cron`

The general scheduling system.

### `crond`

The **daemon/service** that runs in the background and checks scheduled jobs.

### `crontab`

The configuration containing the scheduled jobs.

Think:

```text
crond
  ↓
checks
  ↓
crontab
  ↓
finds a job whose time has arrived
  ↓
runs the command
```

---

# 13. Five Fields in a Crontab

A normal user crontab schedule has **five time/date fields** followed by the command.

```text
* * * * * command
│ │ │ │ │
│ │ │ │ └── Day of week
│ │ │ └──── Month
│ │ └────── Day of month
│ └──────── Hour
└────────── Minute
```

The five fields are:

```text
1st → Minute
2nd → Hour
3rd → Day of month
4th → Month
5th → Day of week
```

---

# 14. Cron Field 1 — Minute

```text
Minute → 0-59
```

Examples:

```text
0
15
30
45
59
```

Example:

```bash
15 * * * * command
```

Means:

> Run at minute 15 of every matching hour.

---

# 15. Cron Field 2 — Hour

```text
Hour → 0-23
```

Examples:

```text
0  → 12 AM
1  → 1 AM
12 → 12 PM
15 → 3 PM
23 → 11 PM
```

---

# 16. Cron Field 3 — Day of Month

```text
Day of month → 1-31
```

Examples:

```text
1
15
20
31
```

Example:

```bash
0 0 15 * * command
```

Means:

> Run at midnight on the 15th day of the month.

---

# 17. Cron Field 4 — Month

```text
Month → 1-12
```

```text
1  → January
2  → February
3  → March
...
12 → December
```

---

# 18. Cron Field 5 — Day of Week

The handwritten note gives:

```text
0-6
```

with:

```text
0 → Sunday
1 → Monday
2 → Tuesday
3 → Wednesday
4 → Thursday
5 → Friday
6 → Saturday
```

### Important

Cron implementations commonly also allow:

```text
7 → Sunday
```

So:

```text
0 = Sunday
7 = Sunday
```

The note correctly says:

> 0 and 7 both are Sunday.

---

# 19. What Does `*` Mean?

In a cron field:

```text
*
```

generally means:

> Every allowed value.

For example:

```bash
* * * * * command
```

means:

> Run the command every minute.

Why?

```text
* → every minute
* → every hour
* → every day of month
* → every month
* → every day of week
```


```text

```

So:

```bash
crontab -e
```

means:

> Open my scheduled Cron jobs so I can add or modify them.

## Command

```bash
crontab -l
```

### Purpose

Lists the current user's Cron jobs.

Breakdown:

```text
crontab → Manage Cron jobs
-l      → List
```

So:

```bash
crontab -l
```

means:

> Show me the Cron jobs belonging to my current user.

---

# 22. Checking Another User's Crontab

The handwritten note shows:

```bash
crontab -l -u username
```

A commonly written form is:

```bash
sudo crontab -u username -l
```

### Purpose

Lists the crontab belonging to another user.

Example:

```bash
sudo crontab -u root -l
```

means:

> List the Cron jobs belonging to the `root` user.

Breakdown:

```text
sudo       → Run with elevated privileges
crontab    → Manage Cron jobs
-u         → Specify a user
root       → The user whose crontab we want
-l         → List the jobs
```

For your own crontab, simply use:

```bash
crontab -l
```

# 31. What is a Shell Script?

The handwritten note on the side refers to:

> Shell Script

A **shell script** is a file containing a group of shell commands that can be executed together.

For example:

```bash
#!/bin/bash

echo "Hello"
date
pwd
```

Instead of typing:

```bash
echo "Hello"
date
pwd
```

one by one, we can put them into a script and execute the script.

Cron can then automatically execute that script.

Example:

```bash
0 1 * * 1-5 /home/ec2-user/backup.sh
```

This means:

> Run the `backup.sh` shell script at 1:00 AM, Monday through Friday.

# 32. Complete Cron Workflow

A simple way to use Cron is:

```text
1. Install Cron/Cronie if necessary
          ↓
2. Check existing jobs
          ↓
   crontab -l
          ↓
3. Edit the Cron schedule
          ↓
   crontab -e
          ↓
4. Add the schedule
          ↓
5. Save and exit
          ↓
6. crond runs in the background
          ↓
7. At the scheduled time
          ↓
8. Cron executes the command/script
```

# 35. Easy Way to Remember Cron

Always read the five stars from **left to right**:

```text
Minute → Hour → Day → Month → Weekday
```

For example:

```bash
0 15 * * 1
```

Read it as:

```text
0      → minute 0
15     → hour 15
*      → any day
*      → any month
1      → Monday
```

Therefore:

> **Monday at 3:00 PM.**
