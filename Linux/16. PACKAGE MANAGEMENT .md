# 2. PACKAGE MANAGEMENT

## What is a Package?

A **package** is a collection of software files and metadata prepared so that software can be installed and managed by a package-management system.

### Important Correction

The handwritten note says:

> "Package, Software, Application and Product all are same."

This is **not technically correct**.

They are related, but they are not the same thing:

| Term | Meaning |
|---|---|
| **Software** | General term for computer programs |
| **Application** | A program designed to perform a particular task |
| **Package** | A distributable bundle containing software files + metadata needed for installation/management |
| **Product** | A broader term; a software product may contain applications, services, documentation, etc. |

### EL5 Example

Suppose you want to install `tree`.

- `tree` → software/application
- `tree-<version>.rpm` → RPM package containing the software
- The package manager → tool that installs, removes, updates, and manages the package.

# 4. RPM

## What is RPM?

**RPM = RPM Package Manager**

Historically, RPM originally stood for **Red Hat Package Manager**, but today the official name is **RPM Package Manager**.

RPM is the lower-level package-management tool used to install, upgrade, remove, query, and verify RPM packages.

An RPM package normally has a filename similar to:

```text
tree-2.1.1-1.el9.x86_64.rpm
```

The exact filename depends on the package version, release, distribution, and architecture.

# 6. RPM VS YUM/DNF

This distinction is extremely important.

## RPM

RPM directly works with RPM package files and the RPM database.

Example:

```bash
sudo rpm -i package.rpm
```

RPM can install the package, but it does **not** function like YUM/DNF as a full repository-based dependency resolver.

---

## YUM / DNF

YUM/DNF works at a higher level.

It can:

- Find packages in configured repositories
- Download packages
- Resolve dependencies
- Install dependencies automatically
- Install the requested package
- Remove packages
- Update packages

### EL5 Explanation

Imagine installing a toy that requires:

```text
Battery
Screw
Controller
```

If you use a tool that understands dependencies, it says:

> "You need the toy, but you also need these three things. I'll get them for you."

That is the important advantage of YUM/DNF.


Example:


### Important Correction

That is **too broad**.

A third-party application does **not** necessarily have to be installed using `rpm`.

If a third-party vendor provides an RPM file, you can often install it using:

```bash
sudo dnf install ./package.rpm
```

This is often preferable to directly using `rpm` because DNF can resolve dependencies.

# 8. DEPENDENCIES

The notes say:

> "Before installing a third party APP we must install dependencies."

The concept is important, but the statement needs refinement.

### What is a dependency?

A dependency is another software component required by an application.

Example:

```text
Application A
     |
     +-- needs Library B
     |
     +-- needs Library C
```

If B and C are missing, Application A may not work.

### With DNF/YUM

Dependencies are normally resolved automatically.

Example:

```bash
sudo dnf install tree
```

DNF checks the package requirements and installs required dependencies when available from configured repositories.

### With direct RPM

For example:

```bash
sudo rpm -i tree.rpm
```

RPM checks dependencies, but it does **not** automatically download missing dependencies from repositories like DNF/YUM does.

Therefore, direct RPM installation may fail if required dependencies are missing.

# 17. `--force`

The handwritten note says:

> "`--force` = to install any app forcefully."

Technically, this needs a warning.

Example:

```bash
sudo rpm -i --force package.rpm
```

`--force` tells RPM to allow certain situations that would normally prevent installation, such as replacing conflicting files/packages in circumstances where RPM permits it.

### IMPORTANT

Do **not** think:

> "`--force` means install anything no matter what."

It does not magically solve every installation problem.

Using `--force` carelessly can damage or overwrite files and create package-management problems.

Therefore:

```text
Use --force only when you understand why it is required.
```

# 18. `--nodeps`

The handwritten note says:

> "`--no deps` = install app without dependency."

The correct RPM option is:

```bash
--nodeps
```

### Meaning

```text
--nodeps
```

→ disables dependency checking for that RPM operation.

Example:

```bash
sudo rpm -i --nodeps package.rpm
```

### IMPORTANT CORRECTION

It does **not** mean:

> "Install the application without dependencies."

It means:

> "Do not check dependencies."

The dependencies may still be required for the application to actually work.

Therefore, using `--nodeps` can leave you with a broken or unusable installation.

### Avoid using this unless you have a specific reason.

# 23. "REMOVE COMPLETELY" — IMPORTANT CORRECTION

The handwritten notes say:

```bash
sudo yum remove Appname
```

under:

> "To Remove completely"

This wording is misleading.

`yum remove` / `dnf remove` removes the package, but you should **not equate it with a universal "purge everything" operation**.

RPM-based package systems do not have a direct equivalent of Debian/Ubuntu's:

```bash
apt purge package
```

in the same sense.

Also, removing a package does not mean:

> "Delete every possible trace, every user-created file, and every configuration file."

Application data and configuration can exist outside the package-managed files.

### For unused dependencies

On DNF-based systems, you may also encounter:

```bash
sudo dnf autoremove
```

which is intended to remove packages that were installed as dependencies and are no longer needed.

Do not use it blindly on production systems; review the transaction first.

# 28. AMAZON LINUX — IMPORTANT MODERN CORRECTION

The notes repeatedly use YUM with AWS/Amazon Linux.

The default package-management tool is:

```bash

```

For example:


Amazon Linux 2023 also provides `yum` as a compatibility command pointing to DNF.

```text

YUM → compatibility command
RPM → lower-level RPM package manager
```

### Easy way to remember

```text

             +---------+---------+
             |                   |
           RPM               DNF/YUM
       Low-level          Higher-level
```

# 31. RPM VS YUM/DNF VS APT — EASY COMPARISON

| Tool | Mainly used with | Main purpose |
|---|---|---|
| `rpm` | RPM-based systems | Low-level RPM package management |
| `dnf` | Modern RPM-based systems | Repository/package management + dependency resolution |
| `yum` | Older/common RPM-based systems | Repository/package management; on Amazon Linux 2023 it points to DNF |
| `apt` | Debian/Ubuntu | Repository/package management + dependency resolution |

### Package formats

```text
RHEL / Fedora / CentOS / Amazon Linux
                    ↓
                  .rpm
                    ↓
             rpm / dnf / yum
```

```text
Ubuntu / Debian
       ↓
     .deb
       ↓
      apt
```

```text
→ Refresh Ubuntu's package information.

sudo apt upgrade
→ Upgrade installed Ubuntu packages.
```

## KEY CORRECTIONS TO REMEMBER

```text
1. Package ≠ software ≠ application ≠ product.
   They are related, but not identical.

2. Amazon Linux should not simply be called a Red Hat-family OS.
   It is RPM-based, but it is an AWS distribution.

3. Amazon Linux 2023 uses DNF as its default package manager.
   yum is available as a compatibility command.

4. Third-party application ≠ must use rpm.
   A third-party RPM can often be installed with DNF as well.

5. rpm -i does NOT automatically download missing dependencies.

6. --nodeps does NOT mean "dependencies are unnecessary."
   It means "do not perform dependency checking."

7. --force should not be used casually.

8. yum remove is not the same concept as Ubuntu's apt purge.

9. wget downloads a file from a URL; it does not download
   software "from a browser to the terminal."

10. Ubuntu uses APT and .deb packages.

11. YUM = Yellowdog Updater, Modified.

12. RPM = RPM Package Manager.
```
