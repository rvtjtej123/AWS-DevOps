# Passwordless Authentication — SSH

> **EL5 idea:**  
> Normally, when you connect to a Linux server, the server asks for your password.  
> With **SSH public-key authentication**, you create a **key pair**:
>
> - **Private key** → stays on your computer. NEVER share it.
> - **Public key** → can be copied to the server.
>
> The server checks whether your private key matches the public key it has stored. If they match, you can authenticate without entering the account password.

---

## 1. Passwordless Authentication

The handwritten note says:

- `PASSWORD LESS AUTHENTICATION`
- `OSI`
- `Trust Relation`
- `Keys Transform`

### Correct technical understanding

For SSH, the important idea is **public-key authentication**.

SSH works over the network using:

- **SSH** → application-level protocol.
- **TCP** → SSH normally uses TCP for its transport connection.
- **Cryptographic key exchange/authentication** → SSH establishes secure cryptographic parameters and can authenticate the user using a public/private key pair.

The handwritten terms `Trust Relation` and `Keys Transform` appear to be referring to the trust established using keys and the SSH key-exchange/authentication process.

> **Important:** SSH public-key authentication is not simply "sending the private key to the server." The private key stays with the client. The client proves possession of the private key cryptographically.

# 2. How to Generate SSH Keys

The note says:

> `How to generate SSH keys ?`

The handwritten command is:

`ssh-keygen`

### What is `ssh-keygen`?

`ssh-keygen` is the OpenSSH utility used to **generate, manage, and convert SSH authentication keys**.

Modern OpenSSH generates an **Ed25519** key when `ssh-keygen` is run without arguments. The note's RSA example therefore needs clarification. :contentReference[oaicite:0]{index=0}

### Recommended modern command

```bash
ssh-keygen
```

- `ssh-keygen` → generates an SSH authentication key pair.
- With current OpenSSH, no `-t` option means **Ed25519** is generated by default.
- The default files are normally:
  - `~/.ssh/id_ed25519` → private key
  - `~/.ssh/id_ed25519.pub` → public key

OpenSSH documents Ed25519 as the default key type in current versions. :contentReference[oaicite:1]{index=1}

# 3. Generating an RSA Key

The handwritten note shows:

```bash
ssh-keygen -t rsa
```

This command is valid.

### Explanation

```bash
ssh-keygen -t rsa
```

- `ssh-keygen` → SSH key-generation utility.
- `-t` → specifies the **type of key** to create.
- `rsa` → tells `ssh-keygen` to create an **RSA** key pair.

Current OpenSSH supports RSA, Ed25519, ECDSA and other key types; Ed25519 is the default when no type is specified. :contentReference[oaicite:2]{index=2}

### If you specifically want RSA

```bash
ssh-keygen -t rsa
```

Typical resulting files:

```text
~/.ssh/id_rsa
~/.ssh/id_rsa.pub
```

- `id_rsa` → **private key**
- `id_rsa.pub` → **public key**

The private key must be kept secret. The public key is the one that gets installed on the server. :contentReference[oaicite:3]{index=3}

---

# 4. Public Key vs Private Key

The handwritten diagram shows:

```text
id_rsa.pub  →  Public key

id_rsa      →  Private key
```

This is correct for an RSA key pair.

## Public key

Example:

```text
id_rsa.pub
```

- `.pub` → indicates the public-key file.
- The public key can be copied to the SSH server.
- It is normally placed in the user's `~/.ssh/authorized_keys` file on the server.

## Private key

Example:

```text
id_rsa
```

- This is the private part of the key pair.
- It must remain secret.
- **Do not copy the private key to the server.**
- **Do not send it to another person.**

OpenSSH specifically states that the private-key file should not be readable by anyone other than the user, while the public-key file does not need to be kept secret. :contentReference[oaicite:4]{index=4}

### Simple way to remember

```text
YOUR COMPUTER                         SSH SERVER
-------------                         ----------
Private key                           Public key
id_rsa                                authorized_keys
id_rsa.pub  ----------------------->  authorized_keys
```

The **public key travels to the server**.

The **private key stays with you**.

# 5. What Happens When `ssh-keygen` Runs?

When you execute:

```bash
ssh-keygen
```

or:

```bash
ssh-keygen -t rsa
```

SSH asks questions such as:

```text
Enter file in which to save the key:
Enter passphrase:
Enter same passphrase again:
```

The handwritten note shows:

```text
location:
Enter
Enter
```

This means that if you simply press **Enter** at the file-location prompt, `ssh-keygen` uses its default filename/location.

For example, for RSA:

```text
~/.ssh/id_rsa
```

and:

```text
~/.ssh/id_rsa.pub
```

The passphrase prompt is separate.

---

# 6. Passphrase

A **passphrase** protects the private key file stored on your computer.

Example:

```text
Enter passphrase (empty for no passphrase):
```

You can:

- enter a passphrase → private key is protected.
- press Enter without entering one → no passphrase is set.

### Important correction

**Passwordless SSH login does NOT necessarily mean the private key has no passphrase.**

For example:

```text
SSH account password
        ↓
not necessarily required

Private-key passphrase
        ↓
may still be requested
```

An SSH authentication agent such as `ssh-agent` can keep an unlocked key available so that you do not repeatedly type its passphrase.

Using a passphrase to protect the private key is strongly preferable to leaving a private key unencrypted, especially for keys stored on normal user machines. WinSCP's documentation also recommends protecting private keys with a passphrase. :contentReference[oaicite:5]{index=5}

# 7. Check Whether the `.ssh` Directory Exists

The handwritten note says:

> `To check .ssh directory is there or not: (ls -a)`

Command:

```bash
ls -a
```

### Explanation

- `ls` → lists files and directories.
- `-a` → shows **all** entries, including hidden entries whose names begin with `.`.
- `.ssh` → is normally a hidden directory because its name starts with `.`.

So:

```bash
ls -a
```

can show:

```text
.
..
.ssh
```

if the `.ssh` directory exists in your current directory.

# 8. Go Inside the `.ssh` Directory

The handwritten note says:

```text
keys will store in .ssh.

(cd .ssh)
```

The idea is correct: user SSH keys are normally stored under the user's `~/.ssh` directory.

A better command is:

```bash
cd ~/.ssh
```

### Explanation

- `cd` → changes the current directory.
- `~` → represents the current user's home directory.
- `.ssh` → the SSH configuration/key directory.
- `~/.ssh` → the `.ssh` directory inside the user's home directory.

You can also use:

```bash
cd .ssh
```

but that works only when your **current directory is already your home directory** and `.ssh` exists there.

### Example

If your home directory is:

```text
/home/ravi
```

then:

```bash
cd ~/.ssh
```

takes you to:

```text
/home/ravi/.ssh
```

### Explanation

You may see:

# 10. Where Does the Public Key Go?

Generating the key pair is only the **first step**.

To use public-key authentication, the server must have your public key in its authorized-keys configuration.

For a normal OpenSSH server, the public key is commonly placed in:

```text
~/.ssh/authorized_keys
```

The server reads public keys from the file specified by `AuthorizedKeysFile`; the normal default includes `~/.ssh/authorized_keys`. :contentReference[oaicite:6]{index=6}

Example:

```text
CLIENT                                      SERVER
------                                      ------

id_rsa                                      ~/.ssh/authorized_keys
(private key)                               (public key)

id_rsa.pub  ----------------------------->  public key
```

### Critical rule

```text
PRIVATE KEY
    ↓
NEVER SHARE

PUBLIC KEY
    ↓
COPY TO SERVER
```

# 11. How Passwordless SSH Authentication Works

Suppose:

```text
Client:
    private key = id_ed25519

Server:
    public key = authorized_keys
```

When you connect:

```bash
ssh username@server
```

the SSH client uses the private key to prove that it possesses the private half corresponding to the public key registered on the server.

The private key itself is **not uploaded to the server**.

If the server accepts the public-key authentication, the user can log in without using the account's normal password.

# 12. Important Correction to the Handwritten `ssh-keygen` Note

The handwritten note effectively presents:

```bash
ssh-keygen
```

and:

```bash
ssh-keygen -t rsa
```

as alternatives.

Both commands work, but they do **not necessarily generate the same type of key**.

### Current OpenSSH

```bash
ssh-keygen
```

→ generates **Ed25519** by default. :contentReference[oaicite:7]{index=7}

### Explicit RSA

```bash
ssh-keygen -t rsa
```

→ generates an **RSA** key pair. :contentReference[oaicite:8]{index=8}

Therefore, do not memorize:

```text
ssh-keygen = RSA
```

That is outdated.

Memorize:

```text
ssh-keygen          → default key type (currently Ed25519)
ssh-keygen -t rsa   → explicitly generate RSA
```

# 13. Windows → Linux SSH

If your client computer is Windows and the server is Linux, you can use an SSH client such as:

- PuTTY
- WinSCP
- Windows OpenSSH
- Other SSH clients

For PuTTY/WinSCP, SSH private keys are commonly handled in **PuTTY's `.ppk` format**. PuTTYgen can generate a public/private key pair and save the private key as a `.ppk` file. :contentReference[oaicite:9]{index=9}

This is different from saying that `.ppk` is an SSH protocol.

### Correct distinction

```text
SSH
↓
Protocol

PPK
↓
Private-key file format commonly used by PuTTY/WinSCP
```

WinSCP documents that private keys can exist in different formats, including PuTTY and OpenSSH formats, and that PuTTYgen can convert between formats. :contentReference[oaicite:10]{index=10}

---

# 14. `.ppk` vs `.pem`

The handwritten notes from this topic may refer to `.ppk` and `.pem`.

Do not confuse them:

### `.ppk`

```text
PuTTY Private Key
```

It is PuTTY's private-key format.

### `.pem`

PEM is a container/encoding style used by many types of cryptographic objects and key files. A file ending in `.pem` is not automatically a particular SSH protocol.

OpenSSH and PuTTY/WinSCP can use different private-key formats, and conversion may be required when moving a key between tools. :contentReference[oaicite:11]{index=11}

# 15. Complete Practical Example

## Step 1 — Generate an Ed25519 key

```bash
ssh-keygen
```

- `ssh-keygen` → creates the SSH key pair.
- Press **Enter** to accept the default file location.
- Enter a strong passphrase when prompted, preferably.

Expected files:

```text
~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub
```

---

## Step 2 — Check the `.ssh` directory

```bash
ls -la ~/.ssh
```

- `ls` → list files.
- `-l` → detailed listing.
- `-a` → include hidden files.
- `~/.ssh` → SSH directory.

---

## Step 3 — Enter the SSH directory

```bash
cd ~/.ssh
```

- `cd` → change directory.
- `~` → your home directory.
- `.ssh` → SSH directory.

---

## Step 4 — Identify the public key

For Ed25519:

```bash
ls -l ~/.ssh/id_ed25519.pub
```

For RSA:

```bash
ls -l ~/.ssh/id_rsa.pub
```

The `.pub` file is the public key.

---

## Step 5 — Install the public key on the server

One common OpenSSH method is:

```bash
ssh-copy-id username@server
```

- `ssh-copy-id` → installs your public key into the remote user's authorized-keys file.
- `username` → username on the remote Linux server.
- `server` → hostname or IP address of the remote server.

After this is configured correctly, you can authenticate using your private key:

```bash
ssh username@server
```

> `ssh-copy-id` is a commonly used helper for installing an SSH public key, but it may not be installed on every Linux/Unix system.
